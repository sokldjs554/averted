모든 데이터는 합성(SYNTHETIC)입니다 — 실제 설비 정보 없음. 숫자는 "현실의 효과"가 아니라 추정 방법이 정답을 맞히는가에 대한 검증입니다. 가정과 한계

averted 점검을 더 하면 고장이 줄까? 로그만 보면 거꾸로 보입니다.

점검한 설비가 더 많이 고장난다 — 점검이 해로운 걸까?

아닙니다. 현장은 위험한 설비를 골라서 점검하기 때문입니다. 로그를 그대로 비교하면 효과의 부호까지 틀립니다.

로그에 보이는 것

4주 안에 비계획 고장이 난 비율 · 점검한 주 vs 점검하지 않은 주

점검 1회가 막은 고장 (%p)

양수 = 점검이 고장을 줄임 · 점 = 추정, 선 = 95% 구간, 점선 = 정답(시뮬레이터가 앎)

왜 거꾸로 보이나 — 위험할수록 점검도 더 하고, 고장도 더 난다

평가 구간의 설비를 위험(점검 여부를 무시한 고장 예측)으로 10등분 · 가로 1 = 가장 안전, 10 = 가장 위험
더 자세히 — 다른 보정 방법(회귀 · IPW)도 같은 답을 내나
보정 방법을 바꿔도 결론이 같은지 보는 견고성 확인입니다. 순진한 비교만 부호가 다릅니다.

같은 점검 횟수로, 누구에게 쓰면 더 많이 막나

효과 추정기 비교 (같은 기준)

정답 효과와의 순위 상관·오차, 그리고 정책 가치. 단순 규칙을 못 이기는 학습 모형은 쓸 이유가 없다.

같은 사이트·같은 주의 같은 K. "정답 보기"를 켜면 각 설비의 실제 효과(시뮬레이터가 아는 값)가 보입니다.

0.10 이하가 관례

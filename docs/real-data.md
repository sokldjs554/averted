# 실제 로그에 적용하기 — 가장 먼저 확인할 것

이 저장소의 숫자는 합성 데이터에서 나왔다. 실제 점검 로그(예: 유비스 마스터의 점검·고장수리·A/S 이력)에 적용할 때는 **효과를 추정하기 전에 식별 가능성부터** 본다. 아래가 그 순서다.

## 1. 로그를 (설비 × 주) 표로 만든다

| 이 저장소의 열 | 실제 로그에서 만드는 법 (예시) |
|---|---|
| `asset`, `week`, `site` | 설비 ID, 결정 시점(주 단위로 내림), 고객사·건물 |
| `treated` | 그 주에 해당 설비의 점검 기록(NFC/비콘 체크)이 한 건이라도 있는가 |
| `y` | 그 주부터 4주 안에 **비계획** 고장 접수(작업지시 유형이 고장수리)가 있었는가. 점검에서 발견해 예방정비로 처리한 건은 고장이 아니다 |
| `grade_last`, `wsv` | 직전 점검의 종합 판정(양호/주의/불량 → 0/1/2), 마지막 점검 후 경과 주 |
| `bd` | 최근 고장의 지수 감쇠 합 (예: 반감기 10주) |
| `cmp` | 최근 민원·A/S 접수의 지수 감쇠 합 — **점검 결정에 가장 강하게 영향을 주는 변수일 가능성이 높다**. 빠뜨리면 교란이 남는다 |
| `open_wo` | 수리 접수(작업지시)가 열려 있는가 |
| `due` | 법정 점검 기한이라 달력으로 점검이 정해진 행 (분석에서 빠진다) |
| `y_prev` | (선택, 권장) 처치 이전 4주의 고장 — 음성 대조 결과 |

열 이름이 다르면 `LogSpec` 으로 매핑한다.

```python
from averted.audit import run_audit
from averted.causal.data import LogSpec
spec = LogSpec(unit="설비ID", time="주", treatment="점검", outcome="고장", site="건물",
               numeric=("연식", "중요도", "직전판정", "경과주", "최근고장", "민원", "수리접수"),
               categorical=("종류",), category_levels={"종류": ["펌프", "냉동기", "공조기"]},
               due="법정기한", prior_outcome="직전4주고장")
report = run_audit(df, spec=spec)
```

## 2. 읽는 순서

1. **`data.rows_excluded_due`** — 법정 점검 행이 얼마나 빠졌나. 점검의 대부분이 달력으로 정해져 있다면 처치 변이가 거의 없어 **효과를 추정할 수 없다**. 이 경우 감사는 "겹침" 경고를 내고, 답은 무작위 파일럿이다.
2. **`overlap`** — 처치 확률이 극단인 행 비율, 유효 표본. 위험한 설비만 점검하는 사이트라면 대조군이 비어 있다.
3. **`balance`** — 가중 후에도 큰 SMD 가 남는 변수가 있나.
4. **`negative_control`** — 점검 이전 고장에 "효과"가 나오면 숨은 교란. 단, **약한 숨은 교란은 못 잡는다** (`docs/failures.md`).
5. **`benchmarks`·`tipping`** — 관측 변수 하나를 뺄 때의 이동량. 추정 효과보다 크면 결론이 숨은 교란 하나에 뒤집힐 수 있다.
6. **`estimates`** — 순진한 비교와 AIPW 의 차이가 클수록 로그의 교란이 크다. AIPW 구간이 0 을 포함하면 말할 수 있는 것이 없다.
7. **`pilot`** — 위 숫자로 계산한 파일럿 규모.

## 3. 무작위 파일럿 프로토콜 (실증 프로젝트에 넣을 것)

1. 고객사 한 곳에서 **법정 점검 대상이 아닌** 설비의 일부(예: 30%)를 무작위로 파일럿 설비로 지정한다.
2. 파일럿 설비는 매주 평소 점검 비율과 비슷한 확률로 **동전 던지기**로 점검 대상을 정한다 (현장이 고르지 않는다).
3. 결과는 점검 이후 4주 안의 비계획 고장. 4주마다 한 시점만 센다(창이 겹치지 않게).
4. 규모는 `POST /v1/pilot/plan` 또는 콘솔의 계획기로 정한다. **전체 설비 대상은 효과가 작아 규모가 매우 커진다**(합성 세계에서 한 고객사의 수 배 이상). 민원이 접수된 설비처럼 효과가 큰 층만 대상으로 하면 규모가 크게 줄어든다.
5. 분석은 평균 차이 + 설비 군집 구간. 보정이 필요 없다. 관측 로그의 AIPW 추정이 이 구간 밖이면 관측 추정을 의사결정에 쓰지 않는다.

## 4. 이 저장소가 실제 로그에서 알려 주지 못하는 것

- 기록되지 않은 교란이 없다는 것. 가정이다. 감사는 위반의 **증거를** 찾을 뿐 **없음을** 증명하지 못한다.
- 점검의 질(깊이, 점검자 숙련도)의 차이. 여기서는 "점검"이 한 가지 행위라고 본다.
- 점검 **프로그램**(주기 변경)의 효과. 추정 대상은 "이번 주 한 번 더"의 효과다.

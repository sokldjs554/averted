# 만든 방식

방향, 수용 기준(완성으로 인정할 조건), "무엇을 주장하지 않을지"는 사람이 정했습니다. 조사, 구현, 측정은 코딩 에이전트(Claude)가 실행했고, 커밋 메시지 끝의 트레일러에도 그렇게 적혀 있습니다.

## 주제를 고른 과정

1. 앞서 만든 저장소(harbinger, 센서 없는 설비의 고장 예측)는 예지보전, 곧 고장을 미리 예측해 정비하는 방식이라 흔하고 복잡해 보인다는 평가를 받았습니다.
2. 다음을 조사했습니다.
   - 회사(디더블유아이)의 최신 기사
   - 채용·합격 후기 (찾지 못했습니다)
   - 국내 유사 프로젝트가 얼마나 많은지 (예지보전, 전력 예측, 안전모 탐지, RAG 챗봇은 이미 너무 많았습니다)
   - 면접관이 포트폴리오에서 보는 것 (문제 정의, 평가 설계, 실패 공개)
   - 후보 주제의 선행 연구
3. 회사가 내세우는 문구는 "장애를 예측하고 최적의 운영 시나리오를 제시"입니다. 이 문구에는 예측 다음 단계, 즉 어디에 손을 쓰면 효과가 있는지가 빠져 있었습니다. 국내 공개 저장소에서 점검의 인과효과(점검이 고장을 얼마나 줄이는지)나 점검 배분(어느 설비를 점검할지 나누는 방식)을 다룬 것은 찾지 못했습니다. 선행 연구는 해외에 있습니다 (`docs/prior-work.md`).

## 판단과 실수

- 처음 시뮬레이터에서는 위험순과 효과순이 같았습니다. 위험순은 고장 위험이 큰 설비부터 점검하는 순서이고, 효과순은 점검해서 막는 고장이 큰 설비부터 점검하는 순서입니다. 효과가 위험과 같은 방향으로만 움직이면 두 순서가 같아져 비교할 이유가 없습니다. 그래서 현장에서 두 순서가 갈라지는 이유(수리 접수된 설비, 순찰로 찾지 못하는 설비, 교체 대상)를 시뮬레이터에 규칙으로 넣었습니다. 이 규칙이 가정이라는 점은 `docs/simulator.md` 에 적었습니다.
- 처음에는 학습한 효과 모형이 위험순을 이기지 못했습니다. 사이트 8~24곳 규모의 초기 실험에서 DR-learner(트리 모형), T-learner, DragonNet 모두 그랬습니다. 셋 다 설비별 효과를 데이터에서 직접 배우는 방법이고, 이 정도 데이터로는 구조 없이 효과를 배우기 어렵다는 결론을 내렸습니다. 구조를 준 모형(반응도)은 여러 고객사의 데이터를 합쳐야(풀링) 이긴다는 것을 학습곡선(학습에 쓴 사이트 수를 늘려 가며 성능을 본 결과)으로 보였습니다. 모형을 시뮬레이터에 맞춰 튜닝하지 않았고, 단순 규칙(수리 접수 제외)을 기준선에 넣었습니다. 작은 데이터에서는 이 규칙이 학습 모형을 이긴다는 점도 그대로 적었습니다.
- 감사가 정상 세계를 빨강으로 표시했습니다. 민감도(기록에 없는 요인에 결론이 얼마나 취약한지)를 신호등 판정에 섞은 탓이었고, 지금은 데이터로 확인되는 문제와 가정 의존도를 따로 표시합니다.
- 파일럿의 검정력(실제로 있는 효과를 놓치지 않을 확률)이 기간을 늘려도 오르지 않았습니다. 같은 설비의 결과가 서로 닮기 때문입니다(설비 내 상관). 계산기가 이런 경우 "도달 불가"라고 답하게 했습니다.
- 병렬로 도는 워커들의 트리 학습이 CPU 코어를 서로 빼앗아 실험이 5배 느려졌습니다(스레드 경쟁). 워커당 스레드를 1개로 고정했습니다.

## AI 사용 공개

코드와 문서의 초안은 에이전트가 썼습니다. 사람이 직접 검토하지 않았을 부분은 테스트로 고정했습니다. 고정한 항목은 아래와 같습니다.
- 정답(포크)이 직접 굴려 센 시뮬레이션 결과와 일치하는지 확인 (`tests/test_world.py`). 포크는 같은 상태를 복제해 점검한 세계와 하지 않은 세계를 따로 돌려 정답을 얻는 방식.
- 추정기가 정답을 아는 자료에서 정답을 되찾는지, econml(인과 추정용 파이썬 라이브러리)의 같은 추정기와 일치하는지 확인 (`tests/test_estimators.py`).
- JS 로 옮긴 파일럿 계획기가 파이썬과 같은 값을 내는지 확인 (`tests/test_pilot_parity.py`).
- 문서의 숫자가 산출물과 일치하는지 확인 (`scripts/fill_numbers.py --check`, CI). CI 는 자동으로 도는 검사.

## 다시 돌려 보기

설치, 전체 파이프라인 실행, 테스트, 콘솔 실행 명령입니다.

```bash
make install && make pipeline     # 시뮬레이션·평가·학습곡선·몬테카를로 (약 1~2시간)
make test
make serve                         # http://localhost:8000/console/
```

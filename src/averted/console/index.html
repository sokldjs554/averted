모든 데이터는 합성(SYNTHETIC)입니다 — 실제 설비·점검자 정보 없음. 시뮬레이터가 점검의 효과를 메커니즘으로 만들고 정답을 알기 때문에, 아래 숫자는 "현실의 효과"가 아니라 추정 방법이 정답을 맞히는가에 대한 검증입니다. 가정과 한계 전부 보기

averted 점검 한 번이 막은 고장을 추정한다 — 위험이 아니라 효과 기준으로 점검 인력을 쓴다

점검한 설비가 더 많이 고장난다 — 점검이 해로운 걸까?

아닙니다. 현장은 위험한 설비를 골라서 점검하기 때문입니다. 로그를 그대로 비교하면 효과의 부호까지 틀립니다.

4주 안에 비계획 고장이 난 비율 · 점검한 주 vs 점검하지 않은 주

점검 1회가 막은 고장 (%p) — 추정 방법별

양수 = 점검이 고장을 줄임 · 점 = 추정, 선 = 95% 신뢰구간, 점선 = 정답(시뮬레이터가 앎)

왜 거꾸로 보이나 — 위험할수록 더 자주 점검한다

평가 구간의 설비를 위험(처치를 무시한 고장 예측) 십분위로 나눈 값

위험할수록 고장도 많다

같은 십분위의 4주 내 고장률 (점검 여부와 무관, 관측값)

같은 점검 횟수로, 누구에게 쓰면 더 많이 막나

사이트·주마다 K 개를 어떤 기준으로 고르는가. 위험순은 "처치를 무시한 고장 예측" — 보통의 예지보전이 하는 일입니다.

점검 100번당 막는 고장

위험과 효과는 다르다

평가 구간의 마지막 주, 전체 사이트 설비 · 가로 = 위험, 세로 = 점검 효과

종류·수리 접수별: 위험 vs 효과

평균 위험이 높아도 효과가 낮은 설비가 있다

고객사를 풀링할수록 배운다

학습에 쓴 사이트 수 → 처음 보는 사이트에서의 점검 100번당 막는 고장 (평균 ± 반복 간 표준편차)

효과 추정기 비교 (같은 기준)

정답 효과와의 순위 상관·오차, 그리고 정책 가치. 단순 규칙을 못 이기는 학습 모형은 쓸 이유가 없다.

이번 주 점검표 — 위험순과 효과순을 나란히

같은 사이트·같은 주의 같은 K. "정답 보기"를 켜면 각 설비의 실제 효과(시뮬레이터가 아는 값)가 보입니다.
